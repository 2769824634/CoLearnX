# 学习路径设计 + 删除 Category（整理稿）

日期：2026-11-11。本文只是设计，**还没有写代码**。

## 一句话总结

把 Learning path 改成真正的学习路径：每个专业一条路径，路径分为 Foundation、Intermediate、Advanced 三个阶段。系统按推荐引导学员逐级学习，但**不拦截报名**。每完成一个阶段颁发阶段证书，三个阶段都完成后颁发 Graduation 证书。Category 列入删除。

## 现状

- `LearningPath` 只有 3 条记录：Professional Skills、Technology、Design。它们只是课程上的一个标签，不包含课程顺序和先修关系。
- 证书阶段目前由课程等级直接决定：Beginner 对应 1（Foundation），Intermediate 对应 2，Advanced 对应 3（见 `CertificatePdf.cs` 的 `CertificateStages.ForLevel`）。每门课单独发一张证书。
- 证书模板一共有 4 个阶段，其中第 4 阶段 Graduation 从来没有被颁发过。

## 已定（2026-11-11 组长确认）

- 路径自动生成，按推荐机制排序：**优先推荐带有相同专业标签、等级更高的课程**。
- 完成一门课的标准：**拿到该课程的课程证书**。
- 推荐的候选和排序：
  1. 候选：与用户已拿证课程有相同专业标签，并且等级不低于已完成最高等级的已发布课程，排除已经报过的课。
  2. 排序：等级高一级的排最前，其次是同级课程；同一档内沿用现有推荐分数（评分 × 0.55 + 兴趣相似度 × 0.30 + 0.15），有近期开班的优先。
  3. 还没有拿到任何证书的用户：按兴趣标签对应的专业，推荐 Foundation 阶段的课程。
- 阶段先修**不拦截报名**：学员可以直接报名任何阶段的课程。先修关系只用于推荐排序和页面提示。

## 设计

### 1. 路径怎么来：每个专业一条，自动生成

- 学习路径 = 专业标签，也就是现有的 12 个 `CourseSubject`，例如 Software Development、Accounting and Finance。
- 每条路径分 3 个阶段，课程的阶段由它的等级决定：Beginner 对应 Foundation，Intermediate 对应 Intermediate，Advanced 对应 Advanced。
- 课程选定专业和等级后，就自动归入对应路径的对应阶段，**不需要管理员手动编排**。
- 这样也和"角色与专业领域设计"一致：同一套专业标签同时用于 Trainer 认证、课程分类和学习路径。

### 2. 先修关系（两层，只做建议，不拦截）

- **阶段先修（自动）**：建议先完成这条路径 Foundation 阶段要求的课程数，再学 Intermediate；Advanced 同理。
- **课程先修（可选）**：Creator 建课时可以指定 0 到 3 门"先修课程"，范围限于同一路径中、阶段不高于本课的课程。这一层用来表示阶段内部的先后顺序。
- 报名时不做检查。未满足先修时，课程详情页显示提示"建议先完成：……"，推荐列表也把这门课排在后面。

### 3. "完成一门课"的定义

建议定义为：该课程的报名状态为 `Completed`，并且已获得这门课的课程证书。这样进度、推荐和阶段证书都和课程证书挂钩，不会出现"没拿到证书却算完成"的情况。

### 4. 证书

| 证书 | 什么时候颁发 | 现状 |
|---|---|---|
| 课程证书 | 完成一门课 | 保留现有流程：Trainer 审核，然后管理员签发 |
| 阶段证书（Foundation / Intermediate / Advanced） | 在一条路径的某个阶段完成要求的课程数 | 新增，复用现有的阶段 1 到 3 模板 |
| Graduation 证书 | 一条路径的三个阶段全部完成 | 新增，复用现有的阶段 4 模板 |

- 阶段证书和 Graduation 证书由系统在条件满足时自动生成，不再经过 Trainer 和管理员审核，因为它们只是对已签发课程证书的汇总。
- 课程证书上不再写阶段名，只写课程名，避免和阶段证书混淆。

### 5. 如何保证路径里的课程有效

路径不存成固定的课程列表，而是每次按条件实时计算。课程一旦不满足条件，就会自动退出路径。

**一门课计入路径，必须同时满足：**

- 状态为 `Published`，即已经通过管理员审核。
- 已经设置专业（`CourseSubjectId`）和等级。
- 课程的 Creator 账号有效、已认证，并且这个专业在 Creator 的专业标签里。
- 管理员没有把它标记为"不计入路径"（新增一个布尔字段 `ExcludedFromPath`）。

**关于开班：** 没有开班的课仍然计入路径，但会显示"暂无开班"。这样路径结构稳定，不会因为排课变化而忽有忽无。

**整条路径只在完整时展示：** 每个阶段的有效课程数都不少于该阶段的要求时，才对 Member 展示这条路径。不完整的路径只有管理员能看到，并显示缺口，例如"Advanced 阶段缺 1 门"。

**管理员审核时把关：** 在现有的课程审核页加三项核对：专业是否选对、等级是否合适、先修课程是否合理。审核通过就意味着这门课进入路径。

**先修关系的校验：**

- 设置时由服务器检查：先修课必须在同一路径内、阶段不高于本课、已发布，最多 3 门，且不能形成循环。
- 设置之后，如果某门先修课下架或被排除，这条先修关系自动失效，不再出现在提示里。

**已经取得的进度不回退：** 学员完成的课程以报名记录和证书为准。即使那门课后来下架，进度仍然算数，已经颁发的阶段证书也不收回。

以上校验约增加 0.5 天工作量。

### 6. 页面

- **Member**：新增"我的学习路径"页面。按阶段列出课程，显示已完成、建议下一步、尚未满足先修三种状态（都可以报名），以及每个阶段的进度（例如 1/2）。
- **课程详情页**：未满足先修条件时，"Reserve place"按钮照常可用，旁边提示"建议先完成：……"。
- **课程目录**：用路径（专业）和阶段筛选，替代现在的 "All learning paths" 和 "All stages"。
- **Creator 建课表单**：去掉 Learning path 下拉框（由专业自动决定），增加可选的"先修课程"多选。

## 删除 Category

不影响任何流程，直接列入删除。和 Staff 一样，只删功能层，数据库列保留不读，避免改表结构。

| 位置 | 删除内容 |
|---|---|
| 后端课程 | `CreateCreatorCourseRequest` / `UpdateCreatorCourseRequest` 里的 `Category`；`CourseService` 的 `category` 筛选参数和赋值；课程列表、详情、管理员审核 DTO 里的 `Category` |
| 后端资料 | 上传资料时的 `category` 参数和返回字段；新上传的资料统一存空字符串 |
| 前端 | `pages/creator/courseCategories.js`；`CourseMaterialsCard` 和 `CreatorCourseFormPage` 里的资料类别下拉框和写死的 `'Design'`；平台课页面的 Category 筛选（该页面本身也会删除）；`businessPresentation.js` 里的 `category` 字段名映射 |
| 保留 | `Courses.Category`、`Materials.Category` 两列，只保留不再读取。**`Interest.Category` 不删**：它是兴趣引导里的分组，和本项无关 |

粗估：0.5 天，含测试修改。

## 数据改动

| 改动 | 说明 |
|---|---|
| `LearningPath` 增加 `CourseSubjectId` | 一个专业对应一条路径，12 条，由种子按 `CourseSubject` 自动生成 |
| 旧的 3 条路径 | 不再使用。课程的 `LearningPathId` 按它的 `CourseSubjectId` 改指到新路径；没有专业的老课程不归入任何路径 |
| `LearningPathStage`（PathId, StageNumber, RequiredCourseCount） | 每个阶段要求完成几门课，默认 1，管理员可以修改 |
| `CoursePrerequisites`（CourseId, PrerequisiteCourseId） | 可选的课程先修关系，每门课最多 3 条 |
| `UserCertificate` 增加可空的 `LearningPathId` | 阶段证书和 Graduation 证书挂在路径上，课程证书挂在课程上 |

## 需要你决定的地方

已定：路径自动生成；以拿到课程证书为完成标准；阶段先修不拦截报名。

1. **每个阶段要完成几门课？** 建议默认 1 门，管理员可以按路径修改。如果要求"完成该阶段所有课程"，那么 Creator 每新增一门课，所有学员的进度都会倒退，所以不建议。
2. **Graduation 证书是否需要管理员签发？** 建议系统自动颁发。
